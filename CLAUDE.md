# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`llm-wiki` is a Textual TUI for a Deep Agent — a Claude Code-style terminal AI interface. The
agent harness comes from [`deepagents`](https://github.com/langchain-ai/deepagents) on top of
LangChain 1.0 + LangGraph; the UI is [Textual](https://textual.textualize.io/). Models come
from any of three providers: `langchain-anthropic`, `langchain-google-genai`,
`langchain-openai`, all routed through `init_chat_model("provider:model")`.

## Toolchain

The project uses **uv** with a local `.venv`. Always run Python through uv:

```sh
uv venv                  # create .venv (one-time)
uv sync                  # install / update deps from pyproject.toml
uv run llm-wiki          # launch the TUI
uv run python -m llm_wiki
uv run pytest            # run tests
uv run ruff check .
```

Python **3.11+** is required (`deepagents` does not support 3.10).

## Architecture

Three-module package — keep the boundaries clean:

1. **`src/llm_wiki/agent.py`** — pure agent factory. UI-agnostic.

   `build_agent(provider, model, working_dir, effort)` returns a `create_deep_agent(...)`
   runnable with `FilesystemBackend(virtual_mode=False)` rooted at `working_dir`, a
   `MemorySaver` checkpointer, and the system prompt formatted with the working directory.

   The chat model is constructed via `init_chat_model(f"{canonical}:{model}", **kwargs)` where
   the kwargs come from `_effort_kwargs(provider, level)` — Anthropic gets
   `thinking={"type": "enabled", "budget_tokens": …}` plus a matched `max_tokens`; OpenAI gets
   `reasoning_effort=<level>`; Gemini gets `thinking_budget=<n>`. `effort="off"` returns `{}`.

   **Single source of truth for providers/models lives here.** `MODELS`, `PROVIDER_LABELS`,
   `PROVIDER_ALIASES`, and `DEFAULT_MODELS` (derived from `MODELS`) are exported and imported
   by `commands.py`. Do not duplicate model lists elsewhere.

   Other module-level constants: `AGENT_RECURSION_LIMIT = 250` (LangGraph graph-iteration cap,
   passed in the `recursion_limit` config), `EFFORT_LEVELS`, `EFFORT_ALIASES` (`middle` and
   `mid` → `medium`).

   The Deep Agent harness already provides `write_todos`, `ls`, `read_file`, `write_file`,
   `edit_file`, `glob`, `grep`, and `task` — do not re-implement them. New custom tools belong
   in a `tools=[...]` argument of `create_deep_agent`.

2. **`src/llm_wiki/commands.py`** — slash-command registry and tab-completion engine.

   Single source of truth shared by the dispatcher (`app._handle_command`) and the suggestion
   bar (`SuggestionBar.show_for`). Each `CommandSpec` has a help string and a list of
   positional `ValueSpec`s. `ValueSpec` is a discriminated union:
   `ChoiceSpec = ("choice", list[str])` or `FreeSpec = ("free", "<placeholder>")`.

   `branches: dict[str, list[ValueSpec]]` makes deeper positional choices depend on a
   previously committed arg — that's how `/model gemini <model-name>` advertises gemini-only
   models. The `/model` branches are auto-generated from `agent.MODELS` × `PROVIDER_ALIASES`,
   so adding a model in `agent.py` automatically appears in the suggestion bar.

   Public helpers: `parse(text) → (committed, prefix, pos)`, `value_spec_at(spec, args, pos)`,
   `candidates(text) → (matches, prefix)`, `complete(text)` (Tab handler — uses
   `os.path.commonprefix` for LCP).

   When you add a command, add it both to `COMMANDS` and to the dispatch dict in
   `app._handle_command`.

3. **`src/llm_wiki/app.py`** — Textual app and entry point glue.

   ### State
   Owned by `LLMWikiApp.__init__`:
   - `launch_dir: Path` — pinned at startup; passed to every `build_agent` call so `/model`
     and `/effort` switches keep the same filesystem root.
   - `provider`, `model`, `effort`, `_debug` — current session config.
   - `agent` — the compiled LangGraph runnable, rebuilt on every `/model` and `/effort`.
   - `thread_id` — regenerated by `_new_thread_id()` on app start, `Ctrl+L`, `/clear`,
     `/model`, and `/effort`. Each `build_agent` creates its own `MemorySaver`, so a new
     agent must use a new thread.
   - `_status_prefix` — `user@host  |  cwd`, computed once via `getpass.getuser()` +
     `socket.gethostname()`; never recomputed on refresh.

   ### Worker (`_run_turn`)
   `@work(exclusive=True)` async worker iterating `agent.astream_events(version="v2")`. Only
   three event kinds are surfaced; everything else (chain start/end, middleware hooks,
   per-token streams from non-agent nodes) is dropped:
   - `on_chat_model_stream` — chunk content split by `_split_chunk` into `(text, thinking)`.
     Text streams into a single growing assistant turn; thinking/reasoning blocks stream into
     a separate `[turn-thinking]` widget. **Both visible regardless of `_debug`.**
   - `on_tool_start` / `on_tool_end` — only rendered when `_debug=True`. Output unwrapping:
     `_format_payload` checks `isinstance(value, BaseMessage)` and uses `.content`.

   When debug is off, tool events do *not* reset the active text turn, so the assistant's
   reply before and after a hidden tool call flows as a single message.

   The agent invocation passes `config={"configurable": {"thread_id": ...}, "recursion_limit": AGENT_RECURSION_LIMIT}`.

   ### Streaming contract
   `astream_events` v2 emits `{event, name, data, metadata, ...}` dicts. Streaming chat-model
   chunks must be appended to a widget that has *finished mounting* — Markdown silently drops
   updates targeted at an unmounted widget. Use `await chat.add_streaming_turn(role)` for any
   turn that will receive `append_to` calls; `chat.add_turn(role, text)` (sync) is fine for
   one-shot turns whose content is final at creation (user messages, system messages, tool
   call/result cards).

   ### Slash commands
   Intercepted in `_on_submit` before any agent call. Handlers: `_cmd_model`, `_cmd_effort`,
   `_cmd_debug`, `_cmd_help`, plus inline lambdas for `clear`/`quit`/`exit`. Keep handlers
   synchronous and render output through `_system_message(...)`. If a command needs to invoke
   the model, dispatch into `_run_turn` instead of calling the agent directly.

   ### Prompt input
   `PromptInput(TextArea)` intercepts keys in `_on_key` (not via `BINDINGS`, because
   TextArea's internal handler needs to be pre-empted before inserting a newline):
   - `enter` → submit · `shift+enter` / `ctrl+j` → newline
   - `tab` → `complete_command(self.text)` from `commands.py`

   `Shift+Enter` requires Kitty-keyboard-protocol-aware terminals (iTerm2, Ghostty, WezTerm,
   kitty). `Ctrl+J` is the universal fallback.

   ### Suggestion bar
   `SuggestionBar(Static)` listens to `TextArea.Changed` on `#prompt` and calls `show_for(text)`
   every keystroke. Logic delegates to `commands.parse` / `commands.value_spec_at` so it can
   never drift from the dispatcher. Keep it pure (no I/O, no state) — it's testable via
   `bar.render()` after `bar.show_for(...)`.

   ### Multi-line input class
   On every text change, `_on_text_changed` calls `set_class("\n" in text, "multiline")` on
   `#input-row`. CSS swaps the `❯` mark from `content-align: left middle` (single-line) to
   `content-align: left top` (multi-line) so the arrow always sits next to the first line.

   ### Status bar
   Bottom-most line, format: `user@host  |  cwd  |  provider:model  |  state  [|  debug]  |  effort:<level>`.
   Always shows `effort:<level>` (including `off`) on the right. `debug` only when active.

## Conventions

- Keep `agent.py` UI-agnostic; the TUI imports the agent, never the reverse.
- New tools belong in a `tools.py` module passed via the `tools=[...]` argument of
  `create_deep_agent`. Don't monkey-patch the harness.
- Subagents go in `subagents=[...]`; remember they don't inherit `skills` — pass them explicitly.
- Long agent calls **must** stay inside a Textual `@work` worker. Calling
  `agent.astream_events` on the main event loop will freeze the UI.
- Streaming widgets must `await chat.add_streaming_turn(...)`; one-shot widgets can use the
  sync `chat.add_turn(...)`.
- Underlying API kwarg names (Anthropic's `thinking={...}`, OpenAI's `reasoning_effort`,
  Gemini's `thinking_budget`) stay literal — they're external contracts, not internal naming.

## Configuration

Environment is read from `.env` (see `.env.example`):

- `ANTHROPIC_API_KEY` — required if using the Anthropic provider.
- `GOOGLE_API_KEY` — required if using the Gemini provider.
- `OPENAI_API_KEY` — required if using the OpenAI provider. Note: `langchain-openai`
  validates this key at construction time, so a `/model openai` switch will fail closed
  (and surface the error as a system message) if it's missing — `langchain-anthropic` does
  not do this, so an Anthropic build can succeed even without a valid key.
- `LLM_WIKI_PROVIDER` — startup default; `anthropic`, `google_genai`, or `openai`
  (default `anthropic`).
- `LLM_WIKI_MODEL` — startup default; falls back to `agent.DEFAULT_MODELS[provider]`
  (which is `MODELS[provider][0]`) if unset. Override at runtime with `/model`.
- `LANGSMITH_*` — optional tracing.

## Slash commands

| Command | Purpose | Handler |
|---|---|---|
| `/model <anthropic\|gemini\|openai> [name]` | Switch the active model. Rebuilds the agent. | `_cmd_model` → `_switch_model` |
| `/effort <off\|low\|medium\|high>` | Reasoning depth. Rebuilds the agent with provider-specific kwargs. Aliases: `middle`, `mid` → `medium`. | `_cmd_effort` → `_switch_effort` |
| `/debug [on\|off]` | Toggle visibility of tool calls/results. No arg → toggle. Reasoning blocks always show regardless. | `_cmd_debug` |
| `/clear` | Clear conversation; new `thread_id`. | `_do_clear` |
| `/help` | List commands. | `_cmd_help` |
| `/quit` / `/exit` | Exit. | `App.exit()` |

`/model`, `/effort`, and `/clear` always reset the conversation thread.
